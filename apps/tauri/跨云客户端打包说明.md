# 跨云客户端打包说明

> **核心结论**：日常开发用 `npm run tauri:dev`；Windows 正式包用 `npm run tauri:build`；**Android 正式 APK 用 `npm run tauri:android:build:release`**（Tag CI 同路径）；`apps/android` **已存档**。  
> **当前版本**：`1.2.8` / code `128`（`package.json` / `tauri.conf.json` / `APP_VERSION_*`；**须完整 semver**）  
> **GitHub 发版铁律**：[docs/guides/GitHub自动打包与密钥配置说明.md](../../docs/guides/GitHub自动打包与密钥配置说明.md) §0 / §9

本文档说明 `apps/tauri` 的环境配置、开发运行、**桌面与 Android 正式打包**、应用内升级、平台能力边界与常见问题。

## 0. 快速上手（先看这里）

### 0.1 日常开发（Windows）

```powershell
cd D:\Code\Go-www\vpn\apps\tauri
npm run setup              # 首次：依赖 + 下载 mihomo
npm run tauri:dev          # 打开跨云桌面窗口（可测 VPN）
```

仅测登录/页面 UI（不能连 VPN）：

```powershell
npm run dev                # 浏览器 http://127.0.0.1:5173
```

### 0.2 打 Windows 正式安装包

```powershell
cd D:\Code\Go-www\vpn\apps\tauri

# 1) 确认版本号（三处一致）
#    - package.json → "version"（须 semver：1.2.2，勿写 1.2）
#    - src-tauri/tauri.conf.json → "version"（同上，否则 cargo/tauri 构建失败）
#    - src/lib/app-meta.ts → APP_VERSION_NAME / APP_VERSION_CODE

# 2) 确认生产 API（.env，不要用 /api 相对路径）
#    VITE_API_BASE_URL=http://192.229.87.112:44080/api

# 3) 发版前检查
npm run preflight:desktop
npm run test

# 4) 构建 NSIS 安装包
npm run tauri:build
```

产物位置：

```text
apps/tauri/src-tauri/target/release/bundle/nsis/
  └── 跨云_1.2_x64-setup.exe            # 给用户安装
apps/tauri/src-tauri/target/release/bundle/
  └── *.nsis.zip / *.sig                 # 若开启 createUpdaterArtifacts，供应用内升级
```

### 0.3 启用应用内升级（可选但推荐）

```powershell
npm run setup:updater      # 生成密钥，写入 tauri.conf.json pubkey，active=true
```

然后：

1. 用私钥签名安装包（见 §14）  
2. 管理后台上传安装包，填写 `updater_signature`  
3. 用户启动客户端会检查更新并提示安装  

私钥在 `apps/tauri/.tauri/updater.key`（已 gitignore，**丢失则无法再签同系列更新**）。

### 0.5 启动 Loading（原生 Splash）

桌面端启动体验已按「Splash 小窗 → 后台加载主 WebView → 就绪后显示主窗」实现，**不是** Vue `/splash` 路由。

```text
进程启动
  → 显示 splash 窗（public/splash.html，品牌 logo + loading）
  → Rust 创建 main 窗（visible:false），后台加载 index.html / Vue
  → Vue mount + router ready（最短约 400ms）
  → invoke boot_reveal_main → main.show → 关闭 splash
  → 进入 Login 或 Connect
```

关键代码：

- [`src-tauri/tauri.conf.json`](src-tauri/tauri.conf.json)：仅配置可见 `splash` 窗
- [`src-tauri/src/lib.rs`](src-tauri/src/lib.rs)：`boot_reveal_main` + 隐藏主窗创建
- [`src/lib/desktop/window-boot.ts`](src/lib/desktop/window-boot.ts)：前端就绪后 reveal
- [`public/splash.html`](public/splash.html) + [`public/splash-logo.png`](public/splash-logo.png)

评估启动速度请用 **正式包**（`tauri:build`），`tauri:dev` 会因 Vite/冷编译偏慢。

## 1. 当前结论

`apps/tauri` 是跨云 **Windows + macOS + Linux + Android + iPhone** 客户端工程。各平台状态如下：

| 平台 | 状态 | 代码位置 | 说明 |
| --- | --- | --- | --- |
| Windows | 可用，需实机验证 | `src-tauri/` + `platforms/windows/` | Mihomo + 系统代理 MVP；正式包 NSIS |
| macOS | 代码支持，需 macOS 实机验证 | `src-tauri/` + `platforms/macos/` | Mihomo + 系统代理；需签名/公证 |
| Linux | 有限支持，需发行版验证 | `src-tauri/` + `platforms/linux/` | gsettings 系统代理；其他 DE 需验证 |
| **Android** | **1.2 起正式发包** | `src/` + `src-tauri/android/` | Vue UI + Mihomo TUN 插件；`tauri:android:build:release` |
| iPhone | Phase A/C ✅；VPN 🚧 xcframework | `platforms/ios/` | SwiftUI + PacketTunnel；见 [iOS xcframework 接入](../../docs/product/iOS-Mihomo-xcframework接入.md) |

功能齐全度与缺口见 [Tauri-Android功能对齐](../../docs/product/Tauri-Android功能对齐.md)。

## 4. 接口域名配置

默认接口（与 Android `releaseAppBaseUrl` 对齐）：

```text
http://192.229.87.112:44080/api
```

注意：只配置到 `/api`，不要写成 `/api/v1`，因为代码里已经统一请求 `/v1/...`。

### 4.1 开发模式（推荐）

`apps/tauri/.env.development` 已配置：

```env
VITE_API_BASE_URL=/api
```

Vite 将 `/api` 代理到远端服务器（见 `vite.config.ts`），解决浏览器访问 `127.0.0.1:5173` 时的 **CORS** 问题。`npm run tauri:dev` 会加载 `.env.development`（覆盖 `.env` 中的同名字段）。

### 4.2 生产构建

使用 `.env` 或 CI 注入完整 URL：

```env
VITE_API_BASE_URL=http://192.229.87.112:44080/api
```

个人覆盖可创建 `.env.local`：

```bash
cd apps/tauri
cp .env.example .env.local
```

临时覆盖（PowerShell）：

```powershell
$env:VITE_API_BASE_URL="https://test.example.com/api"
npm run build
```

### 4.3 验收说明

| 场景 | 在哪里测 |
|------|---------|
| 登录、套餐、节点 UI | 浏览器或 Tauri 窗口均可（开发模式需 `/api` 代理） |
| VPN 一键连接、代理探测 | **仅 Tauri 桌面窗口**（浏览器无 `vpn_connect`） |

## 7. 桌面正式打包

### 7.1 发版前改版本号

三处必须一致（示例升到 `1.0.1`）：

| 文件 | 字段 |
|------|------|
| `package.json` | `"version": "1.0.1"` |
| `src-tauri/tauri.conf.json` | `"version": "1.0.1"` |
| `src/lib/app-meta.ts` | `APP_VERSION_NAME = '1.0.1'`，`APP_VERSION_CODE` 递增（如 `101`） |
| `src-tauri/Cargo.toml` | `version = "1.0.1"`（建议同步） |

`APP_VERSION_CODE` 只增不减，供后台 `has_update` 比较。

### 7.2 Windows 正式包（主路径）

```powershell
cd D:\Code\Go-www\vpn\apps\tauri

# 确认 .env 为生产 API（完整 URL，不是 /api）
Get-Content .env

# 可选：配置 updater（首次或换密钥时）
npm run setup:updater

# 检查
npm run preflight:desktop
npm run test

# 打正式包
npm run tauri:build
```

`tauri:build` 会：

1. 准备 NSIS 打包工具（`fetch-bundle-tools`）  
2. 执行 `npx tauri build`（先前端 `vite build`，再 Rust release）  
3. 产出安装包到 `src-tauri/target/release/bundle/`

常见产物：

```text
src-tauri/target/release/bundle/nsis/跨云_<version>_x64-setup.exe
src-tauri/target/release/bundle/nsis/*.nsis.zip   # updater 用
src-tauri/target/release/bundle/nsis/*.sig        # 签名（有私钥时）
```

如只需要便携 exe：

```powershell
npm run tauri:build:exe
```

Windows 桌面 VPN 当前机制：

- 后端 `/client/config` 返回配置；桌面将 `tun` 转为本地 `mixed` inbound  
- 启动随包 `mihomo.exe`，设置系统 HTTP/HTTPS 代理  
- 连接后探测：`desktop_probe.rs`（`curl HEAD` + 重试）  
- 进程崩溃会转为连接失败并清理代理  

### 7.3 正式包验收清单

安装 `跨云_*_x64-setup.exe` 后确认：

- [ ] 安装后能启动，标题栏/关于页版本为预期  
- [ ] 登录成功，节点/套餐可加载  
- [ ] 选节点后一键连接成功，系统代理已设置  
- [ ] 断开后代理清理  
- [ ] （若启用 updater）启动能拉到更新检查接口

## 8. Android 打包

> **正式 Android 发包路径**（Vue UI + VPN overlay）。  
> `apps/android` **已存档**；其中 `mihomo-core` 仍被本工程 Gradle 引用，勿删。

### 8.1 前置要求

需要安装：

- Android Studio
- Android SDK
- Android NDK
- JDK 17
- Rust Android target

常用 Rust target：

```bash
rustup target add aarch64-linux-android
```

如果需要更多 ABI：

```bash
rustup target add armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

### 8.2 初始化 Android 工程

如果 `src-tauri/gen/android/` 不存在：

```bash
cd apps/tauri
npx tauri android init --ci
```

### 8.3 同步 VPN 原生代码

Tauri 不会自动把 `src-tauri/android/` 的自定义 VPN Kotlin 代码合并到 `gen/android`。本项目已经把同步集成到 Android dev/build 脚本中，日常无需手动执行。

仅在需要单独验证同步结果时执行：

```bash
npm run sync:android-vpn
```

同步内容：

- `VpnPlugin.kt`
- `VpnTunnelService.kt`
- `ConnectivityProbe.kt`
- `VpnConfigPatcher.kt`
- `mihomo/MihomoInitializer.kt`、`ClashConfigSanitizer.kt` 等
- AndroidManifest VPN service / permission
- Gradle `:mihomo-core` 模块（引用存档 `apps/android/mihomo-core`）
- `proguard-rules.pro`

### 8.4 Debug APK

推荐命令：

```bash
cd apps/tauri
npm run tauri:android:build
```

如需构建完成后直接安装到已连接手机：

```bash
npm run tauri:android:build:install
```

产物：

```text
apps/tauri/src-tauri/gen/android/app/build/outputs/apk/arm64/debug/app-arm64-debug.apk
```

说明：

- Debug 包通常很大，可能接近 300MB。
- 主要原因是 Rust debug `.so` 未裁剪，不能作为分发包。
- 该脚本会处理 Windows jniLibs 符号链接失败：失败时自动复制 `.so` 并继续 Gradle 打包。

### 8.5 Release APK

推荐命令：

```bash
cd apps/tauri
npm run tauri:android:build:release
```

如需构建完成后直接安装到已连接手机：

```bash
npm run tauri:android:build:release:install
```

产物：

```text
apps/tauri/src-tauri/gen/android/app/build/outputs/apk/arm64/release/app-arm64-release-debugsigned.apk
```

说明：

- 当前脚本构建 arm64 单 ABI。
- Release 包体积通常约 **40～80MB**，当前约 **64MB**。
- Gradle 会先生成 `app-arm64-release-unsigned.apk`。
- 脚本会用本机 Android debug keystore 签成 `app-arm64-release-debugsigned.apk`，可直接安装做内测。
- debug 签名包不能用于正式上架。

若已经构建过，只想安装最新 Release 包：

```bash
npm run tauri:android:install:release
```

如果手机提示签名不一致：

```bash
npm run tauri:android:install:release:clean
```

该命令会先卸载 `com.vpn.kuayun`，再安装最新 Release 包。

如果只得到 `app-arm64-release-unsigned.apk`，手机安装时可能提示：

```text
解析软件包时出现问题
packageInfo is null
```

原因是 APK 未签名。请安装 `app-arm64-release-debugsigned.apk`。

如果曾手动执行 `npx tauri android build --target aarch64` 导致 symlink 失败，不需要继续手动复制或签名，直接重新执行封装脚本：

```bash
npm run tauri:android:build:release
```

脚本会自动处理同步、复制 `.so`、Gradle 构建和 debug keystore 签名。

### 8.6 Android VPN 行为说明

Android 连接流程：

1. 前端调用 `vpn_prepare`。
2. `VpnPlugin.prepare` 弹出系统 VPN 授权框。
3. 用户确认后，插件通过 `ActivityCallback` 回传真实授权结果。
4. 前端拉取 `/client/config`。
5. `VpnConfigPatcher` 透传 Clash YAML；App 自身在 `openTun` 中 `addDisallowedApplication` 绕过 VPN。
6. `VpnTunnelService` 启动前台服务并调用 Mihomo（`Clash.load` + `startTun`）。
7. 连接成功后，前端通过 Android 原生 `ConnectivityProbe` 做网络探测。

已修复的问题：

- 首次授权确认后仍提示“未获得 VPN 授权”。
- 连接后 WebView 探测误判“隧道已建立，网络不可用”。
- Release 混淆导致 VPN/Mihomo 类可能被裁剪。

### 8.7 安装测试注意事项

- 安装新版前建议先卸载旧版，尤其是 debug 包与 release-debugsigned 包签名不一致时。
- Android 13+ 需要关注通知权限；通知权限不影响 VPN 授权，但会影响前台服务通知显示。
- 如果连接失败，优先抓日志：

```powershell
adb logcat -s VpnTunnelService VpnPlugin Clash
```

## 12. 常见问题

### 12.1 API 请求到了错误路径

检查 `VITE_API_BASE_URL` 是否写成了 `/api/v1`。

正确：

```env
VITE_API_BASE_URL=http://192.229.87.112:44080/api
```

开发模式（`.env.development`）：

```env
VITE_API_BASE_URL=/api
```

错误：

```env
VITE_API_BASE_URL=http://192.229.87.112:44080/api/v1
```

### 12.2 浏览器开发时登录提示「无法连接服务器」

`http://127.0.0.1:5173` 直连远端 API 会被 **CORS** 拦截。确认：

1. 存在 `apps/tauri/.env.development`，且 `VITE_API_BASE_URL=/api`
2. 重启 `npm run dev` 或 `npm run tauri:dev`
3. VPN 连接仍需在 **Tauri 窗口**测试，浏览器不能 invoke `vpn_connect`

### 12.3 Android 构建提示 symbolic link 不允许

Windows 未开启开发者模式会出现该问题。当前构建脚本已自动处理：

```bash
npm run tauri:android:build
npm run tauri:android:build:release
```

也可以开启：

```text
Windows 设置 -> 隐私和安全性 -> 开发者模式
```

### 12.4 Android 构建找不到 cargo

执行：

```powershell
$env:Path="$env:USERPROFILE\.cargo\bin;$env:Path"
```

当前 `scripts/android-build-windows.ps1` 已自动补 PATH。

### 12.5 修改 Android VPN Kotlin 后没有生效

日常直接重新运行 dev/build 命令即可，它们会自动同步：

```bash
npm run tauri:android
```

或：

```bash
npm run tauri:android:build:release
```

如需单独检查同步结果，再执行 `npm run sync:android-vpn`。

### 12.6 Android 安装提示解析失败

不要安装 `app-arm64-release-unsigned.apk`，请安装：

```text
app-arm64-release-debugsigned.apk
```

如果仍无法安装，先卸载旧版：

```bash
adb uninstall com.vpn.kuayun
```

### 12.7 Android 首次授权后仍提示未授权

请确认安装的是包含修复的新包。新包的 `VpnPlugin.prepare` 会等待系统授权结果，不需要第二次点击。

如果仍复现，请抓日志：

```powershell
adb logcat -s VpnTunnelService VpnPlugin Clash
```

### 12.8 Android 连接后显示网络异常

当前已改为 Android 原生探测。如果仍异常，可能是：

- 节点不可达
- DNS 配置异常
- Mihomo 启动失败
- 目标探测站点被网络环境阻断

请抓连接日志：

```powershell
adb logcat -s VpnTunnelService VpnPlugin Clash
```

### 12.9 桌面连接失败

优先检查：

- `src-tauri/resources/bin/mihomo.exe` 是否存在（或执行 `npm run fetch:mihomo`）
- `mihomo.exe -v` 是否可运行
- 后端 `/client/config` 是否返回有效配置（套餐有效、无「账号在其他设备登录」）
- 是否在 **Tauri 窗口**操作（浏览器无法 `vpn_connect`）
- Windows 是否允许设置系统代理
- 连接后约 90s 自动断开：旧策略；**现行** `dataplaneDegradedDisconnectMs=0`（不再定时断隧道）。若仍假连，查探测/数据面逻辑；`dataplane inactive` 应对齐 Android 立即断开
- macOS 是否允许 `networksetup` 修改当前网络服务
- Linux 是否支持 GNOME/gsettings 系统代理

## 14. 桌面内置更新（Tauri Updater）

### 14.1 能力说明

| 模式 | 条件 | 用户体验 |
|------|------|----------|
| **应用内安装** | `plugins.updater.active=true` 且有公钥；后台有签名包 | 启动检查 → 下载安装 → 重启 |
| **外链下载（回退）** | updater 未配置或检查失败 | 启动检查 API → 打开浏览器下载页 |

客户端逻辑见 `src/lib/desktop/updater.ts`：优先 `tauri-plugin-updater`，失败则 `GET /client/version`。

### 14.2 首次配置密钥（每台发版机 / 团队保管一份）

```powershell
cd apps/tauri
npm run setup:updater
```

成功后：

- 私钥：`.tauri/updater.key`（**勿提交 Git**，丢失则旧客户端无法校验新签名）  
- 公钥：`.tauri/updater.key.pub`，并写入 `tauri.conf.json` → `plugins.updater.pubkey`  
- `plugins.updater.active` 变为 `true`  
- endpoint 指向：  
  `http://192.229.87.112:44080/api/v1/client/version/tauri-manifest?target={{target}}&current_version={{current_version}}`

可选：把公钥写入 `.env`：

```env
TAURI_UPDATER_PUBKEY=（公钥整段 Base64）
```

### 14.3 打带升级能力的正式包

```powershell
# 已 setup:updater 且 tauri.conf.json 中 active=true
npm run tauri:build
```

`createUpdaterArtifacts: true` 时，除安装包外还会生成 updater 用的 zip/sig。

签名环境变量（CI 或本机；`npm run tauri:build` 会自动读取 `.tauri/`）：

```powershell
# 推荐：本地已执行 npm run setup:updater，构建脚本自动加载
npm run tauri:build

# 或手动指定（密码必须非空：Windows 会丢弃空环境变量）
$env:TAURI_SIGNING_PRIVATE_KEY = "D:\Code\Go-www\vpn\apps\tauri\.tauri\updater.key"
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = (Get-Content "D:\Code\Go-www\vpn\apps\tauri\.tauri\updater.key.password" -Raw).Trim()
npm run tauri:build
```

若曾用空密码生成密钥导致构建卡住，执行：

```powershell
npm run setup:updater -- -Force
```

### 14.4 后台发布

1. 管理后台 **App 版本** 新建记录：  
   - `platform`：`windows` / `macos` / `linux`  
   - `version_name`：如 `1.0.1`  
   - `version_code`：大于当前客户端 `APP_VERSION_CODE`  
   - 上传安装包 / 填写下载 URL  
   - 填写 `updater_signature`（对应 `.sig` 内容）  
2. Manifest 接口（Tauri 原生 JSON，**不是** `{code,data}` 包装）：  
   `GET /api/v1/client/version/tauri-manifest?target={{target}}&current_version={{current_version}}`

### 14.5 验证升级

1. 安装旧版（如 `1.0.0`）  
2. 后台发布更高 `version_code` 的新包  
3. 启动旧版 → 应弹出「发现新版本」→ 立即更新  
4. 若 updater 失败，至少应能走外链下载回退
